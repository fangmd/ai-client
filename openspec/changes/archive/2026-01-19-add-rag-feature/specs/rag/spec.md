# RAG 功能需求规范

## ADDED Requirements

### Requirement: 知识库管理

系统 SHALL 支持用户创建、管理多个知识库，每个知识库可包含多个文档。

#### Scenario: 创建知识库
- **WHEN** 用户点击"创建知识库"按钮
- **AND** 输入知识库名称（非空，1-50 字符）
- **THEN** 系统创建新知识库并显示在列表中
- **AND** 知识库包含创建时间信息

#### Scenario: 重命名知识库
- **WHEN** 用户选择知识库并点击"重命名"
- **AND** 输入新名称（非空，1-50 字符）
- **THEN** 系统更新知识库名称
- **AND** 列表立即反映新名称

#### Scenario: 删除知识库
- **WHEN** 用户选择知识库并点击"删除"
- **AND** 确认删除操作
- **THEN** 系统删除知识库及其所有文档和向量数据
- **AND** 从列表中移除该知识库

#### Scenario: 查看知识库列表
- **WHEN** 用户打开设置页面
- **AND** 进入知识库管理模块
- **THEN** 系统显示所有知识库列表
- **AND** 每个知识库显示名称、创建时间、文档数量

### Requirement: 文档导入与索引

系统 SHALL 支持用户上传文档到知识库，自动解析、切片、向量化并建立索引。

#### Scenario: 上传 Markdown 文档
- **WHEN** 用户选择 Markdown 文件（.md 格式，≤ 50MB）
- **AND** 选择目标知识库
- **THEN** 系统解析 Markdown 文本内容
- **AND** 文档状态更新为"已就绪"

#### Scenario: 上传 TXT 文档
- **WHEN** 用户选择文本文件（.txt 格式，≤ 50MB）
- **AND** 选择目标知识库
- **THEN** 系统读取文本内容
- **AND** 文档状态更新为"已就绪"

#### Scenario: 文档解析失败
- **WHEN** 文档解析过程中发生错误（如文件损坏、格式不支持）
- **THEN** 系统将文档状态标记为"解析失败"
- **AND** 记录错误信息供用户查看
- **AND** 允许用户删除失败文档或重新上传

#### Scenario: 文档索引进度
- **WHEN** 文档正在索引中
- **THEN** 系统显示索引进度（可选，如"处理中..."）
- **AND** 用户可查看文档状态实时更新

#### Scenario: 刷新文档索引
- **WHEN** 用户选择已索引的文档并点击"刷新索引"
- **THEN** 系统重新解析文档内容
- **AND** 删除旧的切片和向量数据
- **AND** 重新执行切片、向量化和索引流程
- **AND** 文档状态更新为"已就绪"或"失败"

### Requirement: 文本切片

系统 SHALL 将文档文本切分为固定大小的片段，支持重叠以保持语义连续性。

#### Scenario: 自动文本切片
- **WHEN** 文档解析完成
- **THEN** 系统将文本切分为约 500 字符的片段
- **AND** 相邻片段有 10% 的重叠
- **AND** 每个片段保留元数据（如页码、行号）

#### Scenario: 切片存储
- **WHEN** 文本切片完成
- **THEN** 系统将每个片段存储到数据库
- **AND** 片段关联到原始文档
- **AND** 片段包含索引顺序信息

### Requirement: 向量化与存储

系统 SHALL 将文本片段转换为向量并存储到本地向量数据库。

#### Scenario: 本地向量化
- **WHEN** 文本切片完成
- **THEN** 系统使用本地模型（bge-small-zh）将片段向量化
- **AND** 向量存储到 SQLite 向量表
- **AND** 向量维度为 512
- **AND** 所有向量计算在本地完成，数据不离开本地环境

#### Scenario: 向量化失败处理
- **WHEN** 向量化过程中发生错误（如模型加载失败、内存不足）
- **THEN** 系统记录错误信息
- **AND** 跳过失败的片段，继续处理其他片段
- **AND** 文档状态标记为"部分失败"或"失败"

### Requirement: 知识库存储隔离

系统 SHALL 将知识库相关数据存储到独立的 SQLite 数据库中，与主应用数据库分离，且不通过 Prisma 访问该数据库。

#### Scenario: 创建独立数据库
- **WHEN** 用户首次创建知识库
- **THEN** 系统创建或初始化独立的 SQLite 数据库文件用于 RAG 数据
- **AND** 该数据库仅包含知识库元数据、文档、切片与向量相关表
- **AND** 数据库访问使用 SQLite 原生驱动而非 Prisma

#### Scenario: 读写隔离
- **WHEN** 系统执行知识库的增删改查
- **THEN** 仅访问独立的 SQLite 数据库
- **AND** 不写入主应用数据库

### Requirement: RAG 增强对话

系统 SHALL 在对话中集成 RAG 检索，基于知识库内容增强 AI 回答。

#### Scenario: 选择知识库
- **WHEN** 用户在聊天界面选择知识库（从下拉框中选择）
- **THEN** 系统保存该知识库选择到当前会话
- **AND** 后续对话将使用该知识库进行 RAG 检索
- **AND** 如果选择"无"，则禁用 RAG 功能

#### Scenario: 启用 RAG 模式
- **WHEN** 用户在聊天界面选择了知识库（非"无"）
- **THEN** 系统在后续对话中启用 RAG 检索
- **AND** AI 回答基于知识库内容生成

#### Scenario: RAG 检索流程
- **WHEN** 用户发送消息且 RAG 模式已启用
- **THEN** 系统将用户问题向量化
- **AND** 在知识库中执行向量搜索
- **AND** 执行全文搜索（FTS5）
- **AND** 合并搜索结果，取 Top-K 相关片段
- **AND** 应用相关性阈值过滤（默认 0.2）
- **AND** 将片段作为 system message 注入到 LLM Prompt
- **AND** LLM 基于上下文生成回答

#### Scenario: RAG 上下文注入格式
- **WHEN** RAG 检索完成且存在相关片段
- **THEN** 系统将检索结果组装为特定格式的 system message
- **AND** 格式为："以下是检索到的参考内容，请结合引用编号回答：\n\n[1] <文件名> (行 x-y)\n<片段内容>\n\n[2] ..."
- **AND** 每个片段最多截断为 800 字符
- **AND** 片段按相关性排序并编号
- **AND** system message 插入在系统提示词之后、用户消息之前

#### Scenario: 禁用 RAG 模式
- **WHEN** 用户将知识库选择设置为"无"
- **THEN** 系统在后续对话中不使用 RAG 检索
- **AND** AI 回答基于通用知识生成

### Requirement: 引用溯源

系统 SHALL 在 AI 回答中标记引用来源，用户可点击查看原始文档片段。

#### Scenario: 引用标记解析
- **WHEN** AI 返回包含引用标记的内容（如 `cite turn2search0` 或带分隔符的格式）
- **THEN** 系统解析所有引用标记
- **AND** 将引用标记替换为可读的编号格式（如 `[1]`, `[2]`）
- **AND** 按数字顺序排序引用编号
- **AND** 支持多种引用标记格式（纯文本和带分隔符格式）

#### Scenario: 引用标记显示
- **WHEN** AI 回答中包含来自知识库的内容
- **THEN** 系统在回答中显示引用标记（如 `[1]`, `[2]`）
- **AND** 标记在消息渲染时自动解析和替换
- **AND** 标记可点击（未来功能）

#### Scenario: 查看引用来源
- **WHEN** 用户点击引用标记（如 `[1]`）
- **THEN** 系统在侧边栏显示对应的原始文本片段
- **AND** 显示片段所属文档名称
- **AND** 高亮显示匹配的关键内容

#### Scenario: 多个引用
- **WHEN** AI 回答包含多个引用（如 `[1]`, `[2]`, `[3]`）
- **THEN** 系统为每个引用分配唯一编号
- **AND** 用户可分别点击查看每个引用的来源

### Requirement: 上下文控制配置

系统 SHALL 允许用户配置 RAG 检索参数，控制检索结果数量和相关性阈值。

#### Scenario: 配置 Top-K 数量
- **WHEN** 用户调整 Top-K 滑块（范围 1-10，默认 5）
- **THEN** 系统在检索时返回指定数量的相关片段
- **AND** 配置立即生效

#### Scenario: 配置相关性阈值
- **WHEN** 用户调整相关性阈值滑块（范围 0.0-1.0，默认 0.2）
- **THEN** 系统过滤掉相似度低于阈值的片段
- **AND** 配置立即生效
- **AND** 阈值应用于混合搜索的最终分数

### Requirement: 混合搜索

系统 SHALL 同时使用向量搜索和全文搜索，合并结果以提供更好的检索效果。

#### Scenario: 向量搜索执行
- **WHEN** 执行 RAG 检索
- **THEN** 系统使用 sqlite-vec 执行向量相似度搜索
- **AND** 返回相似度分数

#### Scenario: 全文搜索执行
- **WHEN** 执行 RAG 检索
- **THEN** 系统使用 FTS5 执行全文搜索
- **AND** 返回相关性分数

#### Scenario: 结果合并
- **WHEN** 向量搜索和全文搜索都完成
- **THEN** 系统合并两种搜索结果
- **AND** 去重相同片段
- **AND** 按加权分数排序
- **AND** 返回 Top-K 结果

### Requirement: 数据隐私

系统 SHALL 确保所有向量数据和文档内容存储在本地，不发送到外部服务。

#### Scenario: 完全本地化
- **WHEN** 用户使用 RAG 功能
- **THEN** 所有向量计算在本地完成
- **AND** 向量数据存储在本地 SQLite 数据库
- **AND** 文档内容不离开本地环境
- **AND** 无需网络连接即可使用

### Requirement: 性能优化

系统 SHALL 优化文档索引和检索性能，避免阻塞用户界面。

#### Scenario: 异步索引
- **WHEN** 用户上传文档
- **THEN** 系统在后台执行解析和向量化（当前在主线程，未来可迁移到 Worker Thread）
- **AND** 主进程和 UI 不被阻塞
- **AND** 用户可继续使用其他功能
- **AND** 文档状态实时更新（pending → indexing → ready/failed）

#### Scenario: 批量处理
- **WHEN** 文档包含多个文本片段
- **THEN** 系统批量向量化片段（每批 15 个，由 EMBEDDING_BATCH_SIZE 控制）
- **AND** 批量写入数据库
- **AND** 提升处理效率

### Requirement: 错误处理

系统 SHALL 妥善处理各种错误情况，提供清晰的错误信息和恢复机制。

#### Scenario: 文件格式不支持
- **WHEN** 用户上传不支持的文件格式
- **THEN** 系统显示错误提示："不支持的文件格式，请上传 Markdown 或 TXT 文件"
- **AND** 不允许上传

#### Scenario: 文件过大
- **WHEN** 用户上传超过 50MB 的文件
- **THEN** 系统显示错误提示："文件大小超过限制（50MB）"
- **AND** 不允许上传

#### Scenario: 知识库删除确认
- **WHEN** 用户尝试删除包含文档的知识库
- **THEN** 系统显示确认对话框
- **AND** 提示将删除所有文档和向量数据
- **AND** 用户确认后才执行删除
