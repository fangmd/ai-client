# Tool Call 结果存储分析

## 问题

Tools 调用的结果是否需要存储到 message 中？

## 当前实现分析

### 1. 工具调用流程

```
AI Provider (openai-provider.ts)
  ↓ 工具调用完成
  ↓ 执行工具（terminal/read）
  ↓ 生成 formattedResult
  ↓ 调用 callbacks.onToolCallComplete(toolInfo, formattedResult)
  ↓
AI Handler (ai-handler.ts)
  ↓ onToolCallComplete 回调
  ↓ 根据工具类型决定是否存储 resultContent
  ↓ 更新 message.content
```

### 2. 当前存储策略

#### Terminal 工具
- **存储结果**：✅ 是
- **实现位置**：`ai-handler.ts:234-275`
- **逻辑**：
  ```typescript
  const content =
    toolInfo.type === 'terminal' && resultContent
      ? resultContent  // 存储完整执行结果
      : getToolCallCompleteMessage(toolInfo)
  ```
- **前端显示**：`terminal-tool-call-item.tsx` 会显示 `message.content`（执行结果）

#### Read 工具
- **存储结果**：❌ 否
- **实现位置**：`ai-handler.ts:234-275`
- **逻辑**：只存储完成消息（`getToolCallCompleteMessage(toolInfo)`），不存储文件内容
- **前端显示**：无专门组件显示 read 工具结果

#### Web Search / File Search 工具
- **存储结果**：❌ 否
- **实现位置**：`ai-handler.ts:234-275`
- **逻辑**：只存储完成消息（`getToolCallCompleteMessage(toolInfo)`）
- **前端显示**：`tool-call-item.tsx` 只显示状态和查询内容

### 3. 工具结果传递流程

无论是否存储到 message，工具结果都会：
1. **传递给 AI**：作为 `function_call_output` 添加到 `messages` 数组，用于后续递归调用
2. **位置**：`openai-provider.ts:718-744` (read) 和 `openai-provider.ts:876-902` (terminal)

## 存储 vs 不存储的对比

### 方案 A：存储工具调用结果（当前 Terminal 的做法）

#### 优点
1. **用户体验**：
   - 用户可以在历史记录中查看完整的工具执行结果
   - 无需重新执行工具即可查看结果
   - 便于调试和问题排查

2. **数据完整性**：
   - 完整的对话历史记录
   - 可以追溯 AI 的决策依据
   - 支持离线查看

3. **一致性**：
   - Terminal 工具已经存储结果，其他工具也应该保持一致
   - 统一的用户体验

#### 缺点
1. **存储成本**：
   - 工具结果可能很大（特别是 read 工具读取大文件）
   - 增加数据库存储空间
   - 可能影响查询性能

2. **隐私和安全**：
   - 可能包含敏感信息（文件内容、命令输出）
   - 需要额外的安全措施

3. **数据冗余**：
   - 工具结果已经传递给 AI，AI 的回复中可能已经包含了结果摘要
   - 存储原始结果可能造成冗余

### 方案 B：不存储工具调用结果（当前 Read/Web Search 的做法）

#### 优点
1. **存储效率**：
   - 节省数据库空间
   - 减少存储成本

2. **性能**：
   - 消息表更小，查询更快
   - 减少序列化/反序列化开销

3. **隐私**：
   - 敏感信息不会持久化存储
   - 降低数据泄露风险

#### 缺点
1. **用户体验**：
   - 无法查看历史工具执行结果
   - 需要重新执行工具才能查看结果
   - 历史记录不完整

2. **不一致性**：
   - Terminal 工具存储结果，其他工具不存储，体验不一致
   - 用户可能困惑为什么有些工具能看到结果，有些不能

3. **调试困难**：
   - 无法追溯 AI 的决策依据
   - 问题排查困难

## 推荐方案

### 方案 C：选择性存储（推荐）

根据工具类型和结果大小，采用不同的存储策略：

#### 1. Terminal 工具
- **存储**：✅ 完整结果
- **理由**：
  - 命令输出通常不会太大（已有限制：MAX_OUTPUT_LENGTH = 10000）
  - 用户需要查看命令执行结果
  - 当前已实现，用户体验良好

#### 2. Read 工具
- **存储策略**：条件存储
  - **小文件**（< 5000 字符）：✅ 存储完整内容
  - **大文件**（≥ 5000 字符）：❌ 只存储摘要（如："已读取文件 xxx，共 xxx 行"）
- **理由**：
  - 小文件内容对用户有价值
  - 大文件内容可能很大，存储成本高
  - 可以通过摘要告知用户已读取

#### 3. Web Search / File Search 工具
- **存储策略**：❌ 不存储搜索结果
- **理由**：
  - 搜索结果通常很大
  - AI 的回复中已经包含了搜索结果的关键信息
  - 存储成本高，价值相对较低

### 实现建议

#### 1. 修改 `ai-handler.ts` 的 `onToolCallComplete`

```typescript
onToolCallComplete: async (toolInfo: ToolCallInfo, resultContent?: string) => {
  const messageId = toolCallMessageIds.get(toolInfo.itemId)
  if (messageId) {
    try {
      const toolQuery = 
        toolInfo.type === 'terminal' 
          ? toolInfo.command 
          : toolInfo.type === 'read'
          ? toolInfo.filePath
          : toolInfo.query

      // 根据工具类型和结果大小决定存储内容
      let content: string
      
      if (toolInfo.type === 'terminal' && resultContent) {
        // Terminal: 存储完整结果
        content = resultContent
      } else if (toolInfo.type === 'read' && resultContent) {
        // Read: 根据大小决定
        const MAX_STORAGE_SIZE = 5000
        if (resultContent.length <= MAX_STORAGE_SIZE) {
          content = resultContent
        } else {
          // 大文件：存储摘要
          const filePath = toolInfo.filePath || '文件'
          const lineCount = resultContent.split('\n').length
          content = `已读取文件：${filePath}\n共 ${lineCount} 行（内容过大，未完整存储）`
        }
      } else {
        // 其他工具：只存储完成消息
        content = getToolCallCompleteMessage(toolInfo)
      }

      const updatedMessage = await updateMessage(messageId, {
        content,
        status: 'sent',
        toolStatus: toolInfo.status,
        toolQuery
      })

      // ... 通知前端
    } catch (error) {
      // ... 错误处理
    }
  }
}
```

#### 2. 前端显示优化

- **Read 工具**：创建 `read-tool-call-item.tsx` 组件，类似 `terminal-tool-call-item.tsx`
- **显示逻辑**：
  - 如果 `message.content` 是完整内容，显示完整内容
  - 如果是摘要，显示摘要，并提供"重新读取"功能（如果需要）

## 总结

### 当前状态
- ✅ Terminal 工具：已存储结果
- ❌ Read 工具：未存储结果
- ❌ Web Search / File Search：未存储结果

### 推荐改进
1. **保持 Terminal 工具**：继续存储完整结果
2. **改进 Read 工具**：根据文件大小选择性存储
3. **保持 Web Search / File Search**：不存储搜索结果

### 关键考虑因素
1. **用户体验**：用户能否方便地查看历史工具执行结果
2. **存储成本**：结果大小对数据库的影响
3. **一致性**：不同工具之间的体验一致性
4. **实用性**：存储的结果是否对用户有价值
