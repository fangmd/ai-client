# 终端工具 (Terminal Tool) 设计方案

## 一、背景

### 1.1 功能目标

实现一个本地终端工具，允许 AI 在对话中执行终端命令。AI 可以调用此工具执行系统命令（如 `ls`、`cat`、`git status` 等），获取命令执行结果，并基于结果继续对话。

### 1.2 核心价值

- **增强 AI 能力**：让 AI 能够直接操作本地文件系统和执行系统命令
- **提高效率**：用户可以通过自然语言让 AI 执行复杂的终端操作
- **安全可控**：通过权限控制和命令白名单确保安全性

### 1.3 技术选型

- **执行环境**：Node.js `child_process` 模块
- **安全机制**：命令白名单、路径限制、超时控制
- **集成方式**：Function Calling（Chat Completions API）或自定义工具（Responses API）

## 二、方案设计

### 2.1 核心思路

终端工具作为本地工具，需要在客户端执行命令并返回结果。与 OpenAI 内置工具（如 `web_search`）不同，终端工具的执行完全在本地进行。

```
用户消息
  ↓
AI 决定调用终端工具
  ↓
工具调用消息（执行中）
  ↓
执行终端命令（本地）
  ↓
工具调用消息（完成，显示结果）
  ↓
AI 基于结果继续回复
```

### 2.2 技术方案对比

#### 方案A：Function Calling（推荐）

**适用场景**：Chat Completions API 和 Responses API 都支持

**优点**：
- OpenAI 标准 Function Calling 机制
- 支持所有兼容 Function Calling 的模型
- 工具定义清晰（JSON Schema）
- 支持多工具调用
- Responses API 和 Chat Completions API 都支持

**说明**：
- Responses API 支持 Function Calling，但定义方式与 Chat Completions API 略有不同
- Responses API 中函数默认为严格模式（strict），而 Chat Completions 中默认为非严格
- 两种 API 都可以使用 Function Calling 机制

**采用方案：方案A（Function Calling）**

**理由**：
1. 统一使用 Function Calling 机制，代码更简洁
2. 同时支持 Responses API 和 Chat Completions API
3. 标准化的工具定义，易于维护和扩展
4. 与现有架构兼容性好

## 五、核心实现

### 5.1 Tool Executor 实现

```typescript
// src/main/utils/tool-executor.ts

import { exec } from 'child_process'
import { promisify } from 'util'
import { logInfo, logError, logWarn } from './logger'
import * as path from 'path'
import * as os from 'os'

const execAsync = promisify(exec)

/**
 * 命令白名单（允许的命令前缀）
 */
const ALLOWED_COMMAND_PREFIXES = [
  'ls', 'cat', 'head', 'tail', 'grep', 'find', 'which',
  'pwd', 'cd', 'mkdir', 'touch', 'cp', 'mv', 'rm',
  'git', 'npm', 'pnpm', 'yarn', 'node', 'python', 'python3',
  'echo', 'date', 'whoami', 'uname', 'df', 'du',
  'ps', 'top', 'kill', 'killall',
  'curl', 'wget', 'ping',
  // 添加更多安全命令...
]

/**
 * 禁止的命令（危险操作）
 */
const FORBIDDEN_COMMANDS = [
  'rm -rf /', 'rm -rf ~', 'format', 'mkfs', 'dd',
  'shutdown', 'reboot', 'halt', 'poweroff',
  // 添加更多危险命令...
]

/**
 * 最大执行时间（毫秒）
 */
const MAX_EXECUTION_TIME = 30000  // 30秒

/**
 * 最大输出长度（字符）
 */
const MAX_OUTPUT_LENGTH = 10000

/**
 * 执行终端命令
 */
export async function executeTerminalCommand(
  command: string,
  workingDirectory?: string
): Promise<CommandExecutionResult> {
  const startTime = Date.now()
  
  // 1. 安全验证
  if (!validateCommand(command)) {
    throw new Error(`Command not allowed: ${command}`)
  }

  // 2. 确定工作目录
  const cwd = workingDirectory 
    ? path.resolve(workingDirectory)
    : os.homedir()

  // 3. 验证工作目录（必须在用户目录下）
  if (!isPathAllowed(cwd)) {
    throw new Error(`Working directory not allowed: ${cwd}`)
  }

  logInfo('Executing terminal command', {
    command,
    workingDirectory: cwd
  })

  try {
    // 4. 执行命令（带超时）
    const { stdout, stderr } = await Promise.race([
      execAsync(command, {
        cwd,
        maxBuffer: MAX_OUTPUT_LENGTH,
        timeout: MAX_EXECUTION_TIME
      }),
      new Promise<never>((_, reject) => 
        setTimeout(() => reject(new Error('Command execution timeout')), MAX_EXECUTION_TIME)
      )
    ])

    const executionTime = Date.now() - startTime

    // 5. 截断输出（防止过长）
    const truncatedStdout = truncateOutput(stdout)
    const truncatedStderr = truncateOutput(stderr)

    const result: CommandExecutionResult = {
      success: true,
      exitCode: 0,
      stdout: truncatedStdout,
      stderr: truncatedStderr,
      command,
      workingDirectory: cwd,
      executionTime
    }

    logInfo('Terminal command executed successfully', {
      command,
      executionTime,
      outputLength: truncatedStdout.length
    })

    return result
  } catch (error: any) {
    const executionTime = Date.now() - startTime
    const exitCode = error.code || 1

    const result: CommandExecutionResult = {
      success: false,
      exitCode,
      stdout: '',
      stderr: truncateOutput(error.stderr || error.message),
      command,
      workingDirectory: cwd,
      executionTime,
      error: error.message
    }

    logError('Terminal command execution failed', {
      command,
      error: error.message,
      exitCode
    })

    return result
  }
}

/**
 * 验证命令是否允许执行
 */
function validateCommand(command: string): boolean {
  // 1. 检查禁止的命令
  const normalizedCommand = command.trim().toLowerCase()
  for (const forbidden of FORBIDDEN_COMMANDS) {
    if (normalizedCommand.includes(forbidden.toLowerCase())) {
      logWarn('Forbidden command detected', { command, forbidden })
      return false
    }
  }

  // 2. 检查命令前缀
  const firstWord = command.trim().split(/\s+/)[0]
  const isAllowed = ALLOWED_COMMAND_PREFIXES.some(prefix => 
    firstWord.startsWith(prefix)
  )

  if (!isAllowed) {
    logWarn('Command not in whitelist', { command, firstWord })
  }

  return isAllowed
}

/**
 * 验证路径是否允许访问
 */
function isPathAllowed(filePath: string): boolean {
  const resolvedPath = path.resolve(filePath)
  const homeDir = os.homedir()
  
  // 只允许访问用户目录及其子目录
  return resolvedPath.startsWith(homeDir) || 
         resolvedPath.startsWith('/tmp') ||
         resolvedPath.startsWith(process.cwd())
}

/**
 * 截断输出内容
 */
function truncateOutput(output: string): string {
  if (output.length <= MAX_OUTPUT_LENGTH) {
    return output
  }
  
  return output.substring(0, MAX_OUTPUT_LENGTH) + 
    `\n\n[Output truncated. Total length: ${output.length} characters]`
}
```

### 5.2 Provider 层集成（Function Calling）

#### 5.2.1 重要说明：Function Calling 结果返回格式

**关键区别**：Responses API 和 Chat Completions API 在 Function Calling 结果返回上有重要区别：

- **Chat Completions API**：使用 `role: 'tool'` 的消息返回函数调用结果
- **Responses API**：使用 `type: 'function_call_output'` 的 ResponseInputItem 返回函数调用结果

**正确的 Responses API 格式**：
```typescript
{
  type: 'function_call_output',
  call_id: string,  // 必须与 function_call 的 call_id 匹配
  output: string | Array<ResponseInputText | ResponseInputImage | ResponseInputFile>
}
```

#### 5.2.2 Responses API 集成

Responses API 支持 Function Calling，但需要使用 `function_call_output` 类型返回结果：

```typescript
/**
 * 使用 Responses API 进行流式聊天（支持 Function Calling）
 */
private async streamChatWithResponsesAPI(
  messages: AIMessageInput[],
  config: AIConfig,
  callbacks: StreamCallbacks,
  abortSignal?: AbortSignal,
  tools: ToolType[] = []
): Promise<void> {
  try {
    const client = new OpenAI({
      apiKey: config.apiKey,
      baseURL: config.baseURL,
      organization: config.openai?.organization
    })

    // 转换消息格式（支持 Vision API 和 Function Calling）
    // Responses API 的 input 可以是字符串或 ResponseInputItem 数组
    const openaiInput: any[] = []
    
    for (const msg of messages) {
      // 处理 function_call_output 消息
      if ((msg as any)._functionCallOutput) {
        const functionCallOutput = (msg as any)._functionCallOutput
        openaiInput.push(functionCallOutput)
        continue
      }
      
      // 过滤掉 role 为 'tool' 的消息（Chat Completions API 格式，Responses API 不使用）
      if (msg.role === 'tool') {
        continue
      }
      
      // 处理普通消息（user, assistant, system）
      const hasImageAttachments = msg.attachments?.some((a) => a.type === 'image')
      
      if (hasImageAttachments && msg.role === 'user') {
        // Vision API 格式
        const content: any[] = []
        if (msg.content) {
          content.push({ type: 'input_text', text: msg.content })
        }
        msg.attachments
          ?.filter((a) => a.type === 'image')
          .forEach((a) => {
            content.push({
              type: 'input_image',
              source: {
                type: 'base64',
                media_type: a.mimeType,
                data: a.data
              }
            })
          })
        openaiInput.push({
          type: 'message',
          role: 'user',
          content
        })
      } else {
        // 普通消息格式（EasyInputMessage）
        openaiInput.push({
          role: msg.role,
          content: msg.content
        })
      }
    }
    
    // Responses API 的 input 可以是字符串或 ResponseInputItem 数组
    const openaiMessages = openaiInput.length === 1 && typeof openaiInput[0] === 'string' 
      ? openaiInput[0] 
      : openaiInput

    // 构建工具列表
    // Responses API 支持内置工具（web_search, file_search）和自定义 Function Calling
    const toolsList: any[] = []
    
    // 内置工具
    if (tools.includes('web_search')) {
      toolsList.push({ type: 'web_search' })
    }
    if (tools.includes('file_search')) {
      // file_search 需要 vector_store_ids
      // toolsList.push({ type: 'file_search', vector_store_ids: [...] })
    }
    
    // Function Calling 工具（终端工具）
    if (tools.includes('terminal')) {
      toolsList.push(terminalToolDefinition)
    }

    // 构建请求参数
    const requestParams = {
      model: config.model,
      input: openaiMessages,
      stream: true as const,
      ...(toolsList.length > 0 ? { tools: toolsList } : {}),
      ...(config.temperature !== undefined ? { temperature: config.temperature } : {}),
      ...(config.maxTokens !== undefined ? { max_output_tokens: config.maxTokens } : {})
    } as ResponseCreateParamsStreaming

    const stream = await client.responses.create(requestParams, {
      signal: abortSignal
    })

    // 用于跟踪工具调用状态
    const toolCallsMap = new Map<string, ToolCallInfo>()
    // 用于累积 Function Calling 参数
    const functionCallArgsMap = new Map<string, string>()
    // 用于保存 Function Calling 的 call_id（itemId -> call_id）
    const functionCallIdMap = new Map<string, string>()

    // 处理流式响应
    for await (const chunk of stream) {
      if (abortSignal?.aborted) {
        return
      }

      const chunkType = (chunk as any).type

      switch (chunkType) {
        // 处理内置工具调用（web_search, file_search）
        case 'response.output_item.added': {
          const event = chunk as any
          if (event.item?.type === 'web_search_call' || event.item?.type === 'file_search_call') {
            // ... 现有内置工具处理逻辑 ...
          }
          // 处理 Function Calling 工具调用
          else if (event.item?.type === 'function_call') {
            const callId = event.item.call_id || event.item.id
            // 保存 call_id，用于后续返回 function_call_output
            functionCallIdMap.set(event.item.id, callId)
            
            const toolInfo: TerminalToolCallInfo = {
              itemId: event.item.id,
              type: 'terminal',
              status: 'in_progress',
              outputIndex: event.output_index,
              timestamp: Date.now()
            }
            toolCallsMap.set(event.item.id, toolInfo)
            functionCallArgsMap.set(event.item.id, '')
            callbacks.onToolCallStart?.(toolInfo)
          }
          break
        }

        // 处理 Function Calling 参数
        case 'response.function_call.arguments.delta': {
          const event = chunk as any
          // 累积 Function Calling 参数
          // ... 处理逻辑 ...
          break
        }

        // Function Calling 完成
        case 'response.output_item.done': {
          const event = chunk as any
          if (event.item?.type === 'function_call') {
            // 执行函数调用
            const functionName = event.item.name
            const functionArguments = functionCallArgsMap.get(event.item.id) || event.item.arguments || ''
            const callId = event.item.call_id || event.item.id  // 获取 call_id
            
            if (functionName === 'execute_terminal_command') {
              await handleFunctionCall(
                { 
                  name: functionName, 
                  arguments: functionArguments,
                  callId: callId  // 传递 call_id
                },
                messages,
                config,
                callbacks,
                abortSignal,
                options
              )
            }
          }
          break
        }

        // 处理文本输出
        case 'response.output_text.delta': {
          const textDeltaEvent = chunk as ResponseTextDeltaEvent
          if (textDeltaEvent.delta) {
            callbacks.onChunk(textDeltaEvent.delta)
          }
          break
        }

        // ... 其他事件处理 ...
      }
    }

    callbacks.onDone()
  } catch (error) {
    throw error
  }
}

/**
 * 处理 Function Calling
 * 
 * 重要：Responses API 使用 function_call_output 类型返回工具调用结果
 * 而不是 Chat Completions API 的 tool 角色消息
 */
private async handleFunctionCall(
  functionCall: { name: string; arguments: string; callId: string },
  messages: AIMessageInput[],
  config: AIConfig,
  callbacks: StreamCallbacks,
  abortSignal?: AbortSignal,
  options?: { tools?: ToolType[] }
): Promise<void> {
  if (functionCall.name === 'execute_terminal_command') {
    try {
      const args = JSON.parse(functionCall.arguments)
      const { command, workingDirectory } = args

      // 执行命令
      const result = await executeTerminalCommand(command, workingDirectory)

      // 格式化命令结果
      const formattedResult = formatCommandResult(result)

      // 通知工具调用完成
      const toolInfo: TerminalToolCallInfo = {
        itemId: `terminal-${Date.now()}`,
        type: 'terminal',
        status: 'completed',
        command: result.command,
        workingDirectory: result.workingDirectory,
        timestamp: Date.now()
      }
      callbacks.onToolCallComplete?.(toolInfo, formattedResult)

      // 构建 function_call_output 消息（Responses API 格式）
      // 注意：Responses API 使用 function_call_output 类型，而不是 tool 角色
      const functionCallOutput = {
        type: 'function_call_output' as const,
        call_id: functionCall.callId,  // 必须与 function_call 的 call_id 匹配
        output: formattedResult  // 可以是字符串或 ResponseInputText/Image/File 数组
      }

      // 将 function_call_output 添加到消息列表
      // 在消息转换时会将其转换为正确的 ResponseInputItem 格式
      messages.push({
        role: 'user', // 临时使用，实际会在转换时处理
        content: JSON.stringify(functionCallOutput),
        _functionCallOutput: functionCallOutput  // 标记为 function_call_output
      } as any)

      // 递归调用，让 AI 基于结果继续回复
      await this.streamChat(messages, config, callbacks, abortSignal, options)
    } catch (error) {
      logError('Function call execution failed', error)
      callbacks.onError(error instanceof Error ? error : new Error('Function call failed'))
    }
  }
}

/**
 * 格式化命令执行结果
 */
function formatCommandResult(result: CommandExecutionResult): string {
  let output = `Command: ${result.command}\n`
  output += `Working Directory: ${result.workingDirectory}\n`
  output += `Exit Code: ${result.exitCode}\n`
  output += `Execution Time: ${result.executionTime}ms\n\n`

  if (result.stdout) {
    output += `STDOUT:\n${result.stdout}\n\n`
  }

  if (result.stderr) {
    output += `STDERR:\n${result.stderr}\n\n`
  }

  if (result.error) {
    output += `ERROR: ${result.error}\n`
  }

  return output
}

      {command && (
        <div className="mt-2">
          <div className="text-sm font-medium text-gray-700 dark:text-gray-300 mb-1">
            命令：
          </div>
          <div className="bg-black text-green-400 font-mono text-sm p-3 rounded overflow-x-auto">
            {command}
          </div>
        </div>
      )}
      
      {status === 'completed' && message.content && (
        <div className="mt-2">
          <div className="text-sm font-medium text-gray-700 dark:text-gray-300 mb-1">
            输出：
          </div>
          <div className="bg-gray-900 text-gray-100 font-mono text-xs p-3 rounded overflow-x-auto max-h-96 overflow-y-auto">
            <pre className="whitespace-pre-wrap">{message.content}</pre>
          </div>
        </div>
      )}
    </div>
  )
}
```

## 八、安全机制

### 8.1 命令白名单

- 只允许执行白名单中的命令前缀
- 定期更新白名单，添加常用安全命令

### 8.2 路径限制

- 只允许访问用户目录（`~`）及其子目录
- 禁止访问系统目录（`/etc`, `/usr`, `/bin` 等）
- 禁止访问其他用户目录

### 8.3 危险命令检测

- 检测并禁止危险命令（`rm -rf /`, `format`, `shutdown` 等）
- 检测命令注入攻击（特殊字符过滤）

### 8.4 资源限制

- 命令执行超时：30秒
- 输出长度限制：10000 字符
- 内存限制：通过 `maxBuffer` 控制

### 8.5 用户确认（可选）

对于危险操作，可以要求用户确认：

```typescript
// 危险命令列表（需要用户确认）
const DANGEROUS_COMMANDS = [
  'rm -rf', 'git push --force', 'npm publish'
]

// 在执行前检查是否需要用户确认
if (requiresUserConfirmation(command)) {
  // 通过 IPC 请求用户确认
  const confirmed = await requestUserConfirmation(command)
  if (!confirmed) {
    throw new Error('Command execution cancelled by user')
  }
}
```

## 十、技术要点总结

### 10.1 Function Calling 结果返回格式

**核心要点**：Responses API 使用 `function_call_output` 类型返回工具调用结果，而不是 Chat Completions API 的 `tool` 角色消息。

**正确流程**：
1. 从 `function_call` 事件中获取 `call_id` 和完整的 `function_call` 信息
2. 保存 `function_call` 对象（包含 `type: 'function_call'`, `call_id`, `name`, `arguments`）
3. 执行函数调用，获取结果
4. 构建 `function_call_output` 对象：
   ```typescript
   {
     type: 'function_call_output',
     call_id: string,  // 必须与 function_call 的 call_id 匹配
     output: string | Array<ResponseInputText | ResponseInputImage | ResponseInputFile>
   }
   ```
5. **重要**：在递归调用时，需要将 `function_call` 和 `function_call_output` 都添加到 `input` 数组中
   - 先添加 `function_call`（AI 返回的）
   - 再添加 `function_call_output`（我们返回的结果）
6. 递归调用 API，让 AI 基于结果继续回复

**关键点**：API 需要看到 `function_call` 才能匹配 `function_call_output` 的 `call_id`，所以两者都必须包含在 input 中。

**错误做法**（Chat Completions API 格式）：
```typescript
// ❌ 错误：Responses API 不支持 tool 角色
messages.push({
  role: 'tool',
  content: result
})
```

**正确做法**（Responses API 格式）：
```typescript
// ✅ 正确：使用 function_call_output 类型，并包含 function_call
// 1. 保存 function_call 信息
const functionCall = {
  type: 'function_call',
  call_id: callId,
  name: functionName,
  arguments: functionArgs  // JSON 字符串
}

// 2. 构建 function_call_output
const functionCallOutput = {
  type: 'function_call_output',
  call_id: callId,
  output: result
}

// 3. 在递归调用时，将两者都添加到 messages
messages.push({
  _functionCall: functionCall  // 先添加 function_call
})
messages.push({
  _functionCallOutput: functionCallOutput  // 再添加 function_call_output
})

// 4. 在消息转换时，两者都会被添加到 input 数组
```

### 10.2 消息格式转换

Responses API 的 `input` 参数可以是：
- **字符串**：简单的文本输入
- **ResponseInputItem 数组**：包含消息、function_call_output 等

消息转换时需要：
1. 识别 `function_call_output` 消息（通过 `_functionCallOutput` 标记）
2. 直接将其作为 ResponseInputItem 添加到 input 数组
3. 普通消息转换为 `EasyInputMessage` 格式：`{ role, content }`
4. 带图片的消息转换为完整的消息格式，包含 `input_text` 和 `input_image` 内容
