# 文件存储重构设计方案

## 一、背景与目标

### 1.1 当前问题

当前实现将文件以 Base64 编码存储在 SQLite 数据库中，存在以下问题：

1. **数据库膨胀**：Base64 编码会使文件大小增加约 33%，大文件会导致数据库急剧膨胀
2. **性能问题**：每次查询消息都需要加载完整的 Base64 数据，影响查询性能
3. **内存占用**：Base64 字符串占用大量内存，影响应用性能
4. **扩展性差**：难以支持大文件，不适合未来扩展

### 1.2 目标

1. **文件系统存储**：将文件存储在应用缓存目录，数据库只存储文件路径
2. **最小改动**：尽量复用现有代码，最小化修改范围
3. **性能优化**：减少数据库大小，提升查询性能
4. **安全隔离**：Renderer 进程不处理文件数据，只传递文件路径，主进程负责文件操作

## 二、架构设计

### 2.1 存储策略

```
┌─────────────────────────────────────────────────────────────┐
│                      Renderer (前端)                         │
├─────────────────────────────────────────────────────────────┤
│  ChatInput                                                   │
│  ├── 用户选择文件                                            │
│  ├── 获取文件路径（file.path）                               │
│  └── 通过 IPC 发送文件路径和元信息                           │
└────────────────────────────┬────────────────────────────────┘
                             │ IPC (ai:upload-file)
                             │ 传递文件路径、名称、类型、大小
                             ▼
┌─────────────────────────────────────────────────────────────┐
│                      Main (主进程)                           │
├─────────────────────────────────────────────────────────────┤
│  FileHandler                                                 │
│  ├── 接收文件路径和元信息                                    │
│  ├── 从文件路径读取文件数据                                  │
│  ├── 生成唯一文件名（基于 attachmentId）                    │
│  ├── 保存到缓存目录                                          │
│  └── 返回文件路径                                            │
├─────────────────────────────────────────────────────────────┤
│  MessageHandler                                              │
│  └── 创建 Attachment 记录（存储文件路径）                    │
├─────────────────────────────────────────────────────────────┤
│  AttachmentRepository                                        │
│  └── 数据库存储文件路径（而非 Base64）                       │
├─────────────────────────────────────────────────────────────┤
│  OpenAIProvider                                              │
│  └── 需要时从文件路径读取并转换为 Base64                     │
└─────────────────────────────────────────────────────────────┘
```

**设计说明**：
- Renderer 进程只传递文件路径，不处理文件数据，提高安全性
- 主进程负责所有文件操作，包括读取、保存、删除
- 文件从用户选择的原始位置复制到应用缓存目录

### 2.2 文件目录结构

```
userData/
├── data/
│   └── ai.db                    # 数据库文件
├── cache/
│   └── attachments/             # 附件存储目录
│       ├── {attachmentId}.{ext} # 文件命名：附件ID + 原始扩展名
│       └── ...
└── logs/
    └── main.log
```

**开发环境路径**：
- 开发模式：`项目根目录/cache/attachments/`
- 生产模式：`userData/cache/attachments/`

### 2.3 文件命名规则

- **格式**：`{attachmentId}.{ext}`
- **示例**：`1234567890123456789.png`
- **优势**：
  - 唯一性：基于 snowflake ID，保证全局唯一
  - 可追溯：文件名直接对应数据库记录
  - 简单：无需额外的映射表

## 五、实现细节

### 5.1 文件存储工具（FileStorage）

```typescript
// src/main/utils/file-storage.ts

import { app } from 'electron'
import path from 'path'
import { existsSync, mkdirSync, writeFileSync, readFileSync, unlinkSync } from 'fs'
import { logInfo, logError } from './logger'

/**
 * 获取附件缓存目录路径
 */
export function getAttachmentsCacheDir(): string {
  let baseDir: string
  
  if (!app.isPackaged) {
    // 开发模式：项目根目录/cache/attachments
    baseDir = path.join(process.cwd(), 'cache', 'attachments')
  } else {
    // 生产模式：userData/cache/attachments
    const userDataPath = app.getPath('userData')
    baseDir = path.join(userDataPath, 'cache', 'attachments')
  }
  
  // 确保目录存在
  if (!existsSync(baseDir)) {
    mkdirSync(baseDir, { recursive: true })
  }
  
  return baseDir
}

/**
 * 生成文件路径
 * @param attachmentId 附件 ID
 * @param originalName 原始文件名（用于提取扩展名）
 */
export function generateFilePath(attachmentId: bigint, originalName: string): string {
  const cacheDir = getAttachmentsCacheDir()
  const ext = path.extname(originalName) || '.bin'
  const fileName = `${attachmentId}${ext}`
  return path.join(cacheDir, fileName)
}

/**
 * 从源文件路径复制文件到缓存目录
 * @param attachmentId 附件 ID
 * @param sourcePath 源文件路径（用户选择的文件）
 * @param originalName 原始文件名（用于提取扩展名）
 * @returns 文件路径（相对路径）
 */
export function saveFileFromPath(
  attachmentId: bigint,
  sourcePath: string,
  originalName: string
): string {
  try {
    // 检查源文件是否存在
    if (!existsSync(sourcePath)) {
      throw new Error(`Source file not found: ${sourcePath}`)
    }
    
    const targetPath = generateFilePath(attachmentId, originalName)
    
    // 读取源文件并写入目标路径
    const buffer = readFileSync(sourcePath)
    writeFileSync(targetPath, buffer)
    
    logInfo('File saved from path', {
      attachmentId: attachmentId.toString(),
      sourcePath,
      targetPath,
      size: buffer.length
    })
    
    // 返回相对路径（相对于缓存目录）
    const cacheDir = getAttachmentsCacheDir()
    return path.relative(cacheDir, targetPath)
  } catch (error) {
    logError('Failed to save file from path', error)
    throw error
  }
}

/**
 * 读取文件
 * @param filePath 文件路径（相对路径或绝对路径）
 * @returns 文件 Buffer
 */
export function readFile(filePath: string): Buffer {
  try {
    const cacheDir = getAttachmentsCacheDir()
    // 如果是相对路径，拼接缓存目录
    const fullPath = path.isAbsolute(filePath)
      ? filePath
      : path.join(cacheDir, filePath)
    
    if (!existsSync(fullPath)) {
      throw new Error(`File not found: ${fullPath}`)
    }
    
    return readFileSync(fullPath)
  } catch (error) {
    logError('Failed to read file', error)
    throw error
  }
}

/**
 * 删除文件
 * @param filePath 文件路径（相对路径或绝对路径）
 */
export function deleteFile(filePath: string): void {
  try {
    const cacheDir = getAttachmentsCacheDir()
    const fullPath = path.isAbsolute(filePath)
      ? filePath
      : path.join(cacheDir, filePath)
    
    if (existsSync(fullPath)) {
      unlinkSync(fullPath)
      logInfo('File deleted', { path: fullPath })
    }
  } catch (error) {
    logError('Failed to delete file', error)
    // 删除失败不抛出异常，避免影响主流程
  }
}

/**
 * 将文件转换为 Base64（用于 API 调用）
 * @param filePath 文件路径
 * @returns Base64 字符串（不含 data URI 前缀）
 */
export function fileToBase64(filePath: string): string {
  const buffer = readFile(filePath)
  return buffer.toString('base64')
}
```

### 5.2 文件上传 Handler

```typescript
// src/main/handlers/file-handler.ts

import { ipcMain } from 'electron'
import { IPC_CHANNELS } from '@/common/constants'
import { responseSuccess, responseError } from '@/common/response'
import { generateUUID } from '@/main/utils/snowflake'
import { saveFileFromPath } from '@/main/utils/file-storage'
import { logInfo, logError } from '@/main/utils'
import type { UploadFileRequest, UploadFileResponse, IPCResponse } from '@/types'

/**
 * File Handler
 * 处理文件上传相关的 IPC 请求
 */
export class FileHandler {
  /**
   * 注册所有 File 相关的 IPC 处理器
   */
  static register(): void {
    // 上传文件（从文件路径读取并保存）
    ipcMain.handle(
      IPC_CHANNELS.file.upload,
      async (_event, data: UploadFileRequest): Promise<IPCResponse<UploadFileResponse>> => {
        logInfo('【IPC Handler】file:upload called', {
          filePath: data.filePath,
          name: data.name,
          mimeType: data.mimeType,
          size: data.size
        })
        
        try {
          // 生成附件 ID
          const attachmentId = generateUUID()
          
          // 从源文件路径读取并保存到缓存目录
          const filePath = saveFileFromPath(attachmentId, data.filePath, data.name)
          
          const response = responseSuccess<UploadFileResponse>({
            attachmentId,
            path: filePath
          })
          
          logInfo('【IPC Handler】file:upload success', response)
          return response
        } catch (error) {
          const response = responseError(error)
          logError('【IPC Handler】file:upload error', response)
          return response
        }
      }
    )
  }

  /**
   * 注销所有 File 相关的 IPC 处理器
   */
  static unregister(): void {
    ipcMain.removeHandler(IPC_CHANNELS.file.upload)
  }
}
```

### 5.4 前端文件上传流程

```typescript
// src/renderer/src/utils/file.ts

import type { UploadFileRequest, UploadFileResponse, IPCResponse } from '@/types'

/**
 * 上传文件到主进程
 * @param file 文件对象（HTMLInputElement 选择的文件）
 * @returns 附件信息（包含 path）
 */
export async function uploadFile(file: File): Promise<UploadFileResponse> {
  // 在 Electron 中，File 对象有 path 属性（仅在主进程或 preload 中可用）
  // 需要通过 preload 脚本暴露文件路径，或使用其他方式获取路径
  
  // 方案：通过 preload 脚本获取文件路径
  // 注意：需要在 preload 中暴露获取文件路径的方法
  const filePath = (file as any).path
  
  if (!filePath) {
    throw new Error('File path not available. This function requires Electron environment.')
  }
  
  // 通过 IPC 上传文件路径和元信息
  const request: UploadFileRequest = {
    filePath,        // 文件路径（绝对路径）
    name: file.name,
    mimeType: file.type,
    size: file.size
  }
  
  const response = await window.electron.ipcRenderer.invoke('ai:upload-file', request)
  
  if (response.code === 0 && response.data) {
    return response.data
  } else {
    throw new Error(response.msg || 'Failed to upload file')
  }
}
```

**注意事项**：
- Electron 的 File 对象（来自 `<input type="file">`）在 Renderer 进程中可能无法直接访问 `path` 属性
- 需要通过 preload 脚本或使用 `dialog.showOpenDialog` API 获取文件路径
- 或者使用 `electron.dialog.showOpenDialog` 让用户选择文件，直接返回文件路径

### 5.6 前端文件显示

```typescript
// src/renderer/src/utils/file.ts

import type { ReadFileRequest, ReadFileResponse } from '@/types'

/**
 * 获取文件的 data URI（用于前端显示）
 * @param filePath 文件路径
 * @param mimeType MIME 类型
 * @returns data URI 字符串
 */
export async function getFileDataUri(filePath: string, mimeType: string): Promise<string> {
  // 通过 IPC 读取文件并转换为 Base64
  const request: ReadFileRequest = {
    path: filePath,
    mimeType
  }
  const response = await window.electron.ipcRenderer.invoke('ai:read-file', request)
  
  if (response.code === 0 && response.data) {
    return `data:${mimeType};base64,${response.data.data}`
  } else {
    throw new Error(response.msg || 'Failed to read file')
  }
}
```

```typescript
/**

export async function deleteAttachmentsByMessageId(messageId: bigint): Promise<void> {
  // 查询附件记录
  const attachments = await prisma.attachment.findMany({
    where: { messageId }
  })
  
  // 删除文件

    where: { messageId }
  })
```

## 七、注意事项

### 8.1 文件路径存储

- **推荐使用相对路径**：便于迁移和备份
- **绝对路径备选**：如果跨平台兼容性有问题，可以使用绝对路径

### 7.2 文件清理策略

- **删除消息时删除文件**：避免孤立文件占用空间
- **定期清理**：可考虑添加定期清理任务，删除无关联的文件

### 7.3 错误处理

### 7.5 文件选择对话框 Handler

如果需要使用 dialog API，需要添加文件选择 Handler：

```typescript
// src/main/handlers/file-handler.ts

import { dialog } from 'electron'
import { statSync } from 'fs'

// 在 FileHandler.register() 中添加
import type { SelectFilesRequest, SelectFilesResponse, SelectedFileInfo } from '@/types'
import { dialog } from 'electron'
import { statSync } from 'fs'
import path from 'path'

ipcMain.handle(
  IPC_CHANNELS.file.select,
  async (_event, options: SelectFilesRequest): Promise<IPCResponse<SelectFilesResponse>> => {
    try {
      const result = await dialog.showOpenDialog({
        filters: options.filters || [],
        properties: (options.properties as any) || ['openFile']
      })
      
      if (result.canceled || !result.filePaths || result.filePaths.length === 0) {
        return responseSuccess<SelectFilesResponse>({ files: [] })
      }
      
      // 获取文件信息
      const files: SelectedFileInfo[] = result.filePaths.map((filePath) => {
        const stats = statSync(filePath)
        return {
          path: filePath,
          name: path.basename(filePath),
          size: stats.size,
          mimeType: getMimeType(filePath) // 需要实现 MIME 类型检测
        }
      })
      
      return responseSuccess<SelectFilesResponse>({ files })
    } catch (error) {
      return responseError(error)
    }
  }
)
```
