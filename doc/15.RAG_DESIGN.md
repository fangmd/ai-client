# RAG（知识库检索增强）技术方案

## 一、功能概述

本方案为应用增加本地知识库（RAG）能力：用户可以创建知识库、上传文档完成索引；聊天时可选择某个知识库，系统会在发送给大模型前先检索相关片段并注入为系统消息，从而让回答“有据可依”。

### 1.1 功能范围（当前实现）

- **知识库管理**：创建/重命名/删除知识库（Library）
- **文档管理**：上传/列表/删除/刷新索引/查询索引状态（Document）
- **索引**：解析文档内容 → 分块 → 向量化 → 写入本地 RAG 数据库
- **检索**：Hybrid Search（向量检索 + 全文检索）并加权融合
- **聊天注入**：当用户在聊天页选择知识库并启用 RAG 时，主进程在请求大模型前注入检索到的引用片段（system message）

### 1.2 限制与约束（当前实现）

| 约束项 | 当前值 | 说明 |
|---|---:|---|
| 文档类型 | `.md` / `.markdown` / `.txt` | 其他类型会报错（Unsupported document type） |
| 分块大小 | 500 | 默认 `chunkSize = 500` |
| 分块重叠 | 0.1 | 默认 `overlapRatio = 0.1` |
| 向量维度 | 512 | `rag_vector` 定义为 `FLOAT[512]` |
| 索引并发 | 批量 15 条 | embedding 按 `EMBEDDING_BATCH_SIZE=15` 批处理 |
| 检索 TopK | 默认 5 | UI/IPC 可传入覆盖 |
| 过滤阈值 | 默认 0.2 | 仅用于聊天注入阶段（`AIHandler`） |
| 执行线程 | 主线程 | `runWorkerTask` 当前为“直接在主线程执行任务，不使用 Worker” |

## 二、架构设计

### 2.1 总体数据流（索引与查询）

```
┌───────────────────────────────────────────────────────────────────────────┐
│                              Renderer (前端)                               │
├───────────────────────────────────────────────────────────────────────────┤
│ RagStore / RagSelector                                                     │
│ - 选择知识库 selectedLibraryId                                             │
│ - ragConfig: { enabled, topK, threshold }                                  │
│ - 通过 IPC 调用 rag:* APIs 管理知识库与文档                                │
└───────────────────────────────┬───────────────────────────────────────────┘
                                │ IPC (rag:*, ai:stream-chat)
                                ▼
┌───────────────────────────────────────────────────────────────────────────┐
│                               Main (主进程)                                │
├───────────────────────────────────────────────────────────────────────────┤
│ RagHandler (rag:*)                                                         │
│ - uploadDocument → indexDocument                                           │
│   parseDocument → chunkText → insert rag_chunk → embedTexts → rag_vector   │
│ - search → embedTexts(query) → searchHybrid → 取 chunk 内容 + 文档信息     │
│                                                                           │
│ AIHandler (ai:stream-chat)                                                 │
│ - buildRagContext: embedTexts → searchHybrid → threshold 过滤 → 拼 snippets │
│ - 将 snippets 作为 system message 注入到 finalMessages                      │
├───────────────────────────────────────────────────────────────────────────┤
│ RAG DB (better-sqlite3 + sqlite-vec + fts5)                                 │
│ - rag_library / rag_document / rag_chunk                                    │
│ - rag_chunk_fts (fts5)                                                     │
│ - rag_vector (vec0, rowid = rag_chunk.id)                                  │
└───────────────────────────────────────────────────────────────────────────┘
```

### 2.2 模块与职责划分

- **IPC 定义**：`src/common/constants/ipc.ts`
  - `IPC_CHANNELS.rag.*`：RAG 相关操作通道
- **主进程 RAG 入口**：`src/main/handlers/rag-handler.ts`
  - 负责 IPC handler 注册、索引流程调度、检索结果组装
- **主进程 AI 注入**：`src/main/handlers/ai-handler.ts`
  - 在聊天请求中根据 `rag` 参数构建上下文并注入到 `finalMessages`
- **RAG 数据库存取**：`src/main/utils/rag-db.ts` + `src/main/repository/*`
  - 初始化 `rag.db`、建表、CRUD
- **检索实现**：`src/main/utils/hybrid-search.ts` / `fulltext-search.ts` / `vector-store.ts`
  - fts5 + sqlite-vec 的混合检索与融合排序
- **文档解析**：`src/main/utils/document-parser/*`
  - 按扩展名选择解析器，当前读取为 UTF-8 纯文本
- **分块**：`src/main/utils/text-chunker.ts`
  - 固定长度切片 + overlap，附带 offset/line 元信息
- **Embedding**：`src/main/providers/embedding/local.ts`
  - `@xenova/transformers` feature-extraction，WASM 后端，模型：`Xenova/bge-small-zh-v1.5`
- **前端状态与组件**
  - `src/renderer/src/stores/ragStore.ts`：知识库/文档列表、选中库、RAG 参数
  - `src/renderer/src/components/rag/rag-selector.tsx`：聊天页选择知识库（不使用/选择某库）

## 三、数据结构与存储

### 3.1 数据库文件位置

实现位于 `src/main/utils/rag-db.ts`：

- **开发环境（未打包）**：`<projectRoot>/prisma/rag.db`
- **生产环境（已打包）**：`<userData>/data/rag.db`（获取不到 userData 时回退到 `process.cwd()`）

并启用：

- `foreign_keys = ON`
- `journal_mode = WAL`
- `synchronous = NORMAL`
- `cache_size = -64000`
- `better-sqlite3` 的 `defaultSafeIntegers(true)`（使整数默认以 `bigint` 返回）

### 3.2 表结构

RAG 数据库由 `initializeRagDatabase()` 创建以下对象：

- `rag_library`：知识库
- `rag_document`：文档（归属 library）
- `rag_chunk`：分块（归属 document）
- `rag_vector`：向量表（`sqlite-vec` 的 `vec0` 虚表）
  - `rowid` 对齐为 `rag_chunk.id`
  - `embedding FLOAT[512]`
- `rag_chunk_fts`：全文检索表（`fts5` 虚表）
  - 通过触发器与 `rag_chunk` 同步（insert/update/delete）

### 3.3 关键类型

类型定义位于 `src/types/rag-type.ts`：

- `RagLibrary`：`{ id: bigint; name; createdAt; updatedAt }`
- `RagDocument`：`{ id; libraryId; fileName; filePath; fileSize; mimeType; status; errorMessage; ... }`
- `RagChunk`：`{ id; documentId; content; chunkIndex; metadata; createdAt }`
  - `metadata` 目前主要来自 `text-chunker` 的行号与 offset 信息

## 四、索引流程（Document Indexing）

入口在 `src/main/handlers/rag-handler.ts` 的 `indexDocument(document)`，由 `rag:upload-document` 与 `rag:refresh-document` 触发。

### 4.1 流程步骤

1. **标记状态为 indexing**
2. **解析文档**：`parseDocument(filePath)`
   - 通过扩展名选择解析器（Markdown/TXT），读取 UTF-8 内容
3. **文本分块**：`chunkText(content, { chunkSize=500, overlapRatio=0.1 })`
   - 每个 chunk 带 `startOffset/endOffset/startLine/endLine`
4. **写入 chunk 表**：`insertRagChunks(documentId, chunks[])`
   - 写 `rag_chunk`，同时触发器自动维护 `rag_chunk_fts`
5. **向量化并写入 vec 表**
   - 按 `EMBEDDING_BATCH_SIZE=15` 批处理调用 `embedTexts(texts[])`
   - 写入 `rag_vector(rowid=chunkId, embedding)`
6. **完成**：状态更新为 `ready`

### 4.2 失败处理

- 若解析或分块失败：状态变为 `failed`，写入 `errorMessage`
- 若解析成功但分块为空：标记失败并提示 `No content extracted from document`

## 五、检索流程（Hybrid Search）

当前实现存在两条检索入口：

- **RAG 管理页/工具页检索**：`IPC_CHANNELS.rag.search`（`RagHandler`）
- **聊天注入检索**：`buildRagContext()`（`AIHandler`）

### 5.1 向量检索（sqlite-vec）

`src/main/utils/vector-store.ts`：

- 写入：`INSERT OR REPLACE INTO rag_vector(rowid, embedding) VALUES (?, ?)`
- 查询：`WHERE embedding MATCH ? ORDER BY distance LIMIT ?`

返回 `distance`（越小越相似）。

### 5.2 全文检索（fts5 + bm25）

`src/main/utils/fulltext-search.ts`：

- 查询：`rag_chunk_fts MATCH ?`
- 排序：`ORDER BY bm25(rag_chunk_fts) LIMIT ?`

返回 `bm25` 评分（越小越相关）。

### 5.3 Hybrid 融合评分

`src/main/utils/hybrid-search.ts`：

- 默认权重：
  - `vectorWeight = 0.7`
  - `fulltextWeight = 0.3`
- 将两个结果集合并到同一张表（chunkId → score）
- 归一化方式：
  - 向量：`vectorScore = 1 / (1 + distance)`
  - 全文：`fulltextScore = 1 / (1 + bm25Score)`
- 最终分数：

\[
score = vectorScore \cdot vectorWeight + fulltextScore \cdot fulltextWeight
\]

取融合后 TopK。

### 5.4 结果组装

两处都会将 `chunkId` 反查 `rag_chunk.content` 并关联 `rag_document` 信息：

- `RagHandler.search`：返回结构化结果（chunk content + metadata + document 信息）
- `AIHandler.buildRagContext`：拼接为可注入的纯文本片段，并可应用 `threshold` 过滤

## 六、聊天注入策略（AIHandler）

聊天请求由前端 `useAIChat` 通过 `ai:stream-chat` 发送，额外携带：

```ts
rag: {
  enabled: boolean
  libraryId: bigint | null
  topK: number
  threshold: number
}
```

主进程 `src/main/handlers/ai-handler.ts` 的策略：

- 当 `rag.enabled && rag.libraryId` 时：
  - 取最近一条 user message 作为 query
  - 执行 `buildRagContext({ query, libraryId, topK, threshold })`
- 若存在检索结果，则构造一个 **system message** 插入到请求消息列表中：

```
finalMessages = [
  (systemPrompt?),
  (ragContext?),
  ...messages
]
```

注入文本格式（摘要）：

```
以下是检索到的参考内容，请结合引用编号回答：

[1] <fileName> (行 x-y)
<chunk content...>

[2] ...
```

其中每个片段会截断为最多 `RAG_SNIPPET_MAX_LENGTH = 800` 字符，避免 prompt 过大。

## 七、前端交互与状态

### 7.1 选择知识库

`RagSelector` 通过 `Select` 组件展示：

- “不使用知识库”
- `libraries` 列表（来自 `rag:list-libraries`）

切换后更新 `selectedLibraryId`，并在 store 中将 `config.enabled` 置为 `id !== null`。

### 7.2 RAG 参数

`RagStore` 内置默认配置：

- `enabled: false`
- `topK: 5`
- `threshold: 0.2`

当前这些参数会在 `useAIChat` 发起 `ai:stream-chat` 时携带到主进程，用于聊天注入阶段。

## 八、可扩展点与后续建议（不影响当前实现）

以下建议仅作为演进方向，当前实现保持简单可用：

1. **更多解析器**：增加 PDF/Docx/HTML 等解析（建议保持在 `document-parser/*` 分层扩展）
2. **Worker 化**：将 parse/chunk/embed 迁移到 Worker/子进程，避免主线程卡顿
3. **库级过滤**：目前向量/全文检索在全库范围执行，靠 `libraryId` 在后处理阶段过滤；可考虑在检索阶段加入库/文档过滤以降低噪声与提升性能
4. **Embedding 维度可配置**：`rag_vector` 维度固定为 512，与当前模型匹配；如更换模型需同步调整 schema 与重建索引
5. **Prompt 控制**：可按 token 预算对 snippets 做更严格裁剪（目前按字符长度截断）
